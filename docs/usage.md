# 使用与排障

[返回项目首页](../README.md)

## 安装与更新

需要 Apple Silicon Mac、macOS 13 或更新版本，以及已经配置好且正常运行的 Surge 家庭网关。当前不提供 Intel 安装包。

1. 在 [Releases](https://github.com/deepcoldy/surge-watchdog/releases/latest) 下载最新 ZIP，解压后把 `Surge Watchdog.app` 放入 `/Applications` 或 `~/Applications`。系统“应用程序”目录可能要求管理员确认；用户自己的 `~/Applications` 不需要。
2. 打开应用，在“概览”点击“安装后台组件”。组件只安装到当前用户目录，不需要 Xcode、命令行工具或管理员权限。
3. 新安装默认暂停监控。点击“立即检查”，确认网关正常后，开启“自动监控与恢复”。

更新时，退出菜单栏应用，替换 App 并重新打开，再在“概览”点击“更新后台组件”。既有配置和日志会保留；更新后的 UI 恢复需要重新探测。安装失败时，安装器会尝试恢复此前的组件和配置。

从 2.3.0 开始，发行版内包含后台组件。旧版 2.2.0 的 ZIP 只有界面程序，首次使用还需从源码安装后台组件，而且其二进制实际要求 macOS 15。请使用 2.3.0 或更新版本。

## 界面与后台运行

| 位置 | 功能 |
| --- | --- |
| 概览 | 查看健康状态、Gateway VM 地址和最近检查时间；立即检查、UI 安全探测、安装或更新后台组件 |
| 监控日志 | 最新记录在最上方，查看最近 500 行、刷新、打开日志目录 |
| 设置 | 开始或暂停监控、登录启动、Surge UI 恢复、日志保留天数 |
| 菜单栏 | 打开主界面、立即检查、暂停或继续监控、UI 安全探测、打开日志目录、退出应用 |

菜单栏图标会跟随系统自动切换黑白外观；当前状态显示在提示文本和主界面中。

**关闭窗口或退出菜单栏应用，不会停止已经启用的后台监控。** 后台检查由独立的 LaunchAgent 运行。要停止自动恢复，请先关闭“自动监控与恢复”。暂停后，LaunchAgent 仍可能唤醒检查器，但检查器会立即退出，不执行检测或恢复。

“登录后在菜单栏启动”只控制登录后是否显示菜单栏应用，不影响后台监控开关；它不是无需登录就能运行的系统服务。

## 检查和恢复规则

默认每 10 秒检查一次：

1. Surge 主进程是否存在。
2. 从 Surge 生成的 `dhcpd/server.json` 读取网关模式、DHCP、Gateway VM 地址和接口。
3. DHCP 进程是否存活，Gateway VM 是否具有有效的 ARP 邻居。
4. Fake DNS 地址 `198.18.0.2` 是否响应。

Gateway VM 地址每次重新发现，不依赖固定 IP。DNS 检查使用保留域名 `surge-watchdog.invalid`，不依赖公网连通性。**这些是本机组件检查，不代表已经验证所有家庭设备或公网连接正常。**

默认连续失败 3 次后尝试恢复；两次恢复至少间隔 120 秒，每小时最多 3 次。

恢复顺序：

1. 已启用 UI 恢复且 Surge 正在运行时，优先尝试定向恢复：网关模式开启则点击齿轮菜单中的“重启服务”，关闭则尝试完成启用向导。
2. 再次执行健康检查，确认恢复结果。
3. UI 恢复未启用、不可用或失败时，调用官方 `surge-cli --raw stop` 安全停止 Surge；CLI 失败时仅使用普通 `SIGTERM`，不使用 `SIGKILL`。
4. 重新打开 Surge，在 60 秒内重复健康检查；必要时可在重启后再尝试 UI 恢复。

启用向导仅接受 `Ethernet / 以太网` 接口。它可以重新启用 IPv4 DHCP，但不会填写或修改静态地址、子网、路由器、DNS、IPv6 RA、VM 网关或地址池字段。未知页面、未知弹窗或接口不匹配时会停止 UI 操作，并记录失败。

本项目不操作 UniFi 配置，不自动切换到直连路由，也无法解决宽带故障、Mac 断电、死机或网卡失效。

## 可选的 UI 恢复与权限

普通健康检查、官方 CLI 恢复和重启整个 Surge 不需要辅助功能权限。只有 UI 定向恢复需要授权，权限应授予 **Surge Watchdog**，不需要授权 Terminal。

启用步骤：

1. 在“隐私与安全性 → 辅助功能”中允许 Surge Watchdog。
2. 回到“概览”，运行“UI 安全探测”。
3. 探测成功后开启“Surge UI 恢复”。

安全探测会打开 Surge 主窗口、切换到“设备”、读取网关模式、展开齿轮菜单确认“重启服务”存在，最后关闭菜单。**探测不会开关网关模式或重启服务。**

UI 恢复要求当前用户已经登录且屏幕未锁定。遇到普通弹窗，只会尝试明确的“稍后 / 取消 / 关闭 / 跳过”等按钮；未知弹窗会停止操作，避免误点升级、导入、删除或授权确认。

### 已授权，为什么仍提示需要权限？

把 App 放在固定的安装路径，并优先使用正式签名的发行版。开发阶段使用 ad-hoc 签名反复替换二进制，可能导致 macOS 不再认可旧权限身份；Developer ID 签名能保持更稳定的身份。

如果系统设置已开启，但应用仍判断未授权，可在应用中使用“修复授权…”。它只清理本应用的旧权限条目与探测状态，再由当前版本重新请求授权。

**权限授权和安全探测是两回事。** 升级后台组件后，会关闭旧的 UI 恢复开关并清除探测结果；即使权限还在，也需要重新探测成功后才能启用。

## 日志与配置

| 内容 | 本机路径 |
| --- | --- |
| 配置 | `~/Library/Application Support/surge-watchdog/config` |
| 按日日志 | `~/Library/Logs/Surge Watchdog/` |
| 后台检查器 | `~/Library/Application Support/surge-watchdog/bin/surge-watchdog` |

日志默认保留 7 天，可在设置中调整为 1–90 天。后台每小时至多清理一次，应用读取日志时也会补充清理。旧版的 `~/Library/Logs/surge-watchdog.log` 仍可显示，新记录写入按日文件。

常用设置可在界面修改；高级参数见 [config.example](../config.example)，包括失败阈值、冷却时间、每小时恢复上限和验证时长。真实配置保存在用户目录，不应提交到仓库。

命令行只读检查：

```sh
~/Library/Application\ Support/surge-watchdog/bin/surge-watchdog --status
```

`--status` 只报告状态，**不会执行恢复**。手动关闭 Surge 或网关模式做排查前，应先暂停监控，避免自动恢复与手动操作相互干扰。

项目没有遥测或日志上传功能。反馈问题时，请先去除日志中的家庭网络地址、设备名称和其他个人信息。参见 [安全与隐私](../SECURITY.md)。

## 卸载

先暂停监控并退出菜单栏应用，然后在源码目录运行：

```sh
./scripts/uninstall.sh
```

脚本会停止两个 LaunchAgent，删除安装到 `~/Applications` 的应用和后台运行脚本；配置、状态和日志默认保留。放在 `/Applications` 的 App 需自行移到废纸篓。

若不再使用，可自行删除上述用户目录中的配置、状态和日志；这些数据保留并不会继续执行监控。
